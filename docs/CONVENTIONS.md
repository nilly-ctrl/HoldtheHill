# Naming and layout conventions (proposal)

Proposal from Nilly, 2026-10-14. The [README](../README.md) is the rule; this page fills in what it
leaves open, so code moved out of a sandbox lands in the same shape every time. Where it differs
from the README it says so, and the README wins until the team agrees.

Sources: the README (PascalCase, namespaces follow folders, one folder per feature, `Shared/`
and `Core/`) and *Level Up!* (short dev names with location and order, an abbreviation table,
naming rules for scenes, assets and audio).

## Rules

1. **Folders say where, names say what.** A class is named for its role, never for where it came
   from or who wrote it: `BuildBar`, not `GrayboxBuildBar`. No project or owner prefix on scripts
   or prefabs; the folder is the prefix.
2. **One feature, one folder**, with the README's subfolders (`Scripts/`, `Prefabs/`, `Data/`,
   `Art/`, ...). A one-script feature still uses `Scripts/`, so every feature reads the same way.
3. **Namespaces follow folders**: `HoldTheHill.Features.Hud`, `HoldTheHill.Core.Save`,
   `HoldTheHill.EditorTools.Builders`.
4. **Code every feature uses goes in `Core/`** (save, localization, input, animation player, UI
   kit). `Core/` never depends on `Features/`.
5. **Pictures that are not one feature's sprites** go to `Shared/Art/<Kind>/`: `Icons/`, `Ui/`,
   `Tilesets/`, `Animations/`; fonts to `Shared/Fonts/`.
6. **Dev tools are a feature** (`Features/DevTools/`), fenced with
   `#if UNITY_EDITOR || DEVELOPMENT_BUILD` so release builds do not carry the console.
7. **Editor code lives in `_Game/Editor/<Area>/`**: `Builders/`, `Authoring/`, `Validation/`,
   `Pipeline/`, namespace `HoldTheHill.EditorTools.<Area>`.
8. **Tests mirror features**: `Tests/PlayMode/<Feature>Tests.cs`, `Tests/EditMode/<Feature>Tests.cs`,
   namespace `HoldTheHill.Tests`.
9. **Renames keep the GUID**: move with `git mv` so the `.meta` travels; rename file and class
   together. A renamed *field* needs `[FormerlySerializedAs("oldName")]`.
10. **Generated prefabs are regenerated by their builder**, not moved or edited by hand.

## Where this differs from the README (team to decide)

| Topic | README today | Proposal | Why |
|---|---|---|---|
| Data asset names | `ArcherTower.prefab` + `ArcherTowerData.asset` | Same stem, told apart by folder: `Prefabs/Grunt.prefab`, `Data/Grunt.asset` | The folder already says it is data; shorter names in pickers |
| Level scenes | `Levels/Hill01/Hill01_Terrain`, `Hill01_Gameplay` | `Levels/L01_Kitchen/L01_Kitchen_Terrain`, `L01_Kitchen_Gameplay`; the player name ("Kitchen Floor") lives in the level data asset | Order and place in one sortable dev name, as the book suggests |
| Abbreviations | — | `L` level, `B` boss, `H` hazard, `W` wave set | One table, no clashes |
| Audio files | PascalCase | `mus_L01_waves.ogg`, `sfx_place_01.wav`, `ui_click.wav` | Sorts the audio folder by kind; the usual industry form |
| Feature folders | `UI/`, `DebugTools/`, `Player/` | `Hud/` and `Menus/` instead of one `UI/`; `DevTools/`; `Hero/` for the Warden (`Player/` is empty) | `UI/` was getting both in-run and shell screens |
| Assemblies | One `HoldTheHill.Runtime` | Runtime, plus own assemblies for the UI kit, dev tools and validation | Dev tools stay out of release builds by assembly; faster recompiles. New asmdefs are a team call |

## Names that clash once a prefix is dropped

When the graybox moved into `_Game`, dropping "Graybox" gave clashes. How they were settled, as
an example for the next move:

- A subclass that only existed to extend a team class is **folded into it**
  (`GrayboxTowerPlacer` into `TowerPlacer`, `GrayboxBaseHealth` into `Queen`,
  `GrayboxEconomy` into `WalletBehaviour`).
- Where two classes really do two jobs, both stay with role names: `GameFlowController` (core)
  and `RunFlow` (what a run is).
- Too-generic results get one more word: `Settings` → `GameSettings`, `Controls` → `GameControls`.
- A name already taken by another kind of thing gets the catalog name: the graybox melee tower
  is `SoldierTower`, because `MeleeTower` is a weapon.
- Save-file keys are not renamed (the level id `Graybox` stays as a key so old saves load).
