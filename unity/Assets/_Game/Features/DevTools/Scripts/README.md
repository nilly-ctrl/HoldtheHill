# Dev tools (runtime debug)

Console, live tuning, replay recorder and performance overlay for the graybox. Everything in this
folder is wrapped in `#if UNITY_EDITOR || DEVELOPMENT_BUILD`, so it is not in release builds.
Input uses the Input System package (the project's only input handler); the panels are IMGUI.

## Add it to a scene

- `Tools > Hold the Hill > DevTools > Add DevTools To Open Scene` adds a `DevTools` object with a
  `DevToolsBootstrap`. Save the scene to keep it.
- `Tools > Hold the Hill > DevTools > Create DevTools On Play` (a toggle) creates one on Play in any
  scene that has a `GrayboxGameFlow`. Use this for generated scenes, which a rebuild would wipe.

## Console commands

`help [cmd]`, `list [commands|enemies|towers|resources|skills|achievements]`,
`spawn <enemy> [n]`, `nextwave`, `skipwave`, `setgold <n>`, `give <resource> <n>`
(gold, honeydew, skillpoints, or a resource asset id), `god [on|off]`, `speed <x|reset>`,
`kill all`, `win`, `lose`, `unlock [all|skills|achievements]`, `tune`, `perf`,
`rec start|stop|status`, `replay list|play <file|latest>|stop|status`.

Add your own from any code: `DevCommandRegistry.Default.Register("name", "usage", "help", args => "result");`.

Notes: `skipwave` clears the field and moves the spawner past the next wave without spawning it
(not available on the last wave). `unlock` writes achievements to the real save file.
`speed` overrides the time scale only while playing; pausing and the pause menu keep their own.
`god` refills the hill from inside its health-changed event and heals the Warden each frame.

## Live tuning

Tower mode follows the selected tower. Enemy mode shows the enemy picked with F3. It lists the
float, int, bool and enum fields of the HoldTheHill components on the object (found by
reflection). Edit, nudge by 10%, "Apply to all" (same name, alive now), "Reset".
"Copy to data asset" (Editor only) writes the changed values into the prefab the object came from,
through `SerializedObject`, and saves. "Copy as text" puts the changes on the clipboard.

Limits: a script that copies a number in Awake/Start will not see a later change. Tower numbers
live on the tower prefab (not `TowerData`), so that is what is written. Enemy, boss and pickup
prefabs are regenerated by their builders on every build, so a value written to them is lost on the
next rebuild: change the builder as well. Tower cost is not tunable here (it is on the data asset).

## Replays

`rec start` ... `rec stop` writes `persistentDataPath/replays/replay-<time>-<map>-seed<seed>.json`.
Set `Auto Record Runs` on the bootstrap to record every run and save it when the run ends.
`replay play latest` starts a new run, sets `UnityEngine.Random` to the recorded seed and gives the
game the same commands on the same fixed-step ticks.

Recorded: tower place, sell, upgrade (from the `GrayboxTowerPlacer` events), Warden
ability use (with where the Warden stood), skill unlocks, campaign wave starts, field resets
(restart or retry wave) and console commands.

### Determinism limits (read before trusting a replay)

- It replays commands, not frames. A command that cannot be applied (cost, blocked cell, ability on
  cooldown) is skipped and counted as a desync; the console log lists the first few.
- Only `UnityEngine.Random` is seeded, once, at the start. Game code that draws numbers in
  Update-driven order (chain lightning jitter, mine placement, splitter offsets, power-up spawns,
  the mega horde) gets the same seed but a different call order whenever frame timing differs.
- Much of the game runs in `Update` with `Time.deltaTime` (cooldowns, movement, the Warden), so
  results depend on frame rate. Fixed-step ticks only fix when commands are *issued*.
- Warden movement is not recorded. Abilities teleport the Warden to where it stood.
- Mouse-collected pickups and power-ups are not recorded. Speed changes and pausing are not.
- A tower removed in a way other than selling it would be recorded as a sell.
- Recording started mid-run cannot rebuild what was already built (flagged in the file and warned on
  play). Endless waves are procedural and are not recorded as commands.
- Treat a replay as "the same inputs again", good for reproducing a build order, not a guarantee of the
  same outcome.

## Performance overlay

FPS, average and worst frame time over the last 120 frames (real time), counts of enemies, towers,
projectiles and pickups, enemies still walking the path, and GC bytes allocated last frame (profiler
counter; Editor and development builds). Counts refresh four times a second. The overlay's own text
drawing adds to the GC number.
